# SMS port trace foundation

This host-only, single-threaded shim samples uncalibrated raw counters before
forwarding each read/write to the original function. It uses no Python callback
in the port hot path. Static disassembly suggests the candidate GX counter
reflects instruction-end cycles, but this is an unverified hypothesis, not a
proven timestamp. The fake-core tests do not establish the GX hook, cycle
offset, ABI, or 270-unit seed spacing.
An embedded version string and ad-hoc signature do not establish a clean build.

`just c-test` includes the strict C fake-core stress check, and
`just python-test` discovers the fake-core Python tests. Run
`just sms-port-trace-sanitizer` separately for the ASan/UBSan stress check;
it requires a compiler with both sanitizers.

An internally vetted, hash-specific layout with a known symbol extent and
aligned in-bounds counter offset, plus the required symbols, installed pointer
identities and 1<<20 cycle ratio, is required before pointer installation.
No GX layout is registered: the actual Z80 symbol extent is not yet verified,
so even the pinned GX hash fails closed. The tests temporarily register only
their own fake-core layout. Run only on a quiescent core after
initialization, with no other thread invoking ports or changing slots, ratio,
or the loaded core. Bracket every core frame with `begin_frame` / `end_frame`,
using consecutive frame numbers; read `events()` only between frames, and use
the context manager to restore slots before unloading the core. A trace context
cannot be entered more than once. Storage is bounded; overflow, calls outside
frames, or ratio changes are failures. Raw counters may reset between frames:
there is no inferred cross-frame time or wrap correction. A decrease within a
frame fails. The shim is a singleton and only one trace can be active. Cleanup
is owner-checked and preserves replaced slots; a further exception during
cleanup is reported on the original error, and an existing trace object can
retry `close()`.

The manager retains active owners and both library handles. If construction
or context entry fails and cleanup is interrupted, the original exception
normally exposes `trace_owner`; call `trace_owner.retry_cleanup()` after the
interruption.
If that attribute is unavailable, inspect `retained_traces()` to identify the
failed owner. That list also contains healthy active traces: never blindly
clean up another owner's trace. A failed constructor or context entry cannot
run trace operations, even if it acquired native ownership; retry cleanup
for any retained owner.
Native trace operations also verify the owner token and both slot addresses.
Do not unload or run a core with unresolved
ownership. Entry guard interruptions preserve an already-entered outer owner;
failed first-entry cleanup is attempted even if marking the owner fails.
Python cannot make exception handling atomic: further asynchronous interruptions
can interrupt decisions, cleanup, exception preservation or retry guidance.
Keep the process alive, inspect retained owners, and retry cleanup as needed.
Interrupted frame transitions permanently invalidate the trace: do not use
its events, and close it to restore hooks.

The shim uses the matching upstream GX Z80 slot types: byte-valued port reads
and byte-valued write data, with an unsigned-int port. The fake tests exercise
these C signatures, not the ABI or behavior of a live GX library.
The core file must remain immutable between hashing and loading, and the
process must not already have a different image loaded under the same path;
the file hash is not an attestation of the in-memory image.

`check_seed(events)` checks only the ordered low-eight-bit port, value and kind
sequence generated by `build_sms_rom`, and 270-unit adjacent gaps within one
frame. It detects missing, duplicate and unexpected events under that
comparison, but ignores upper port bits. Real GX calibration must independently
validate full port values. Passing this check alone does not calibrate the hook.
There is deliberately no emulator runner in this first pass. An eventual
opt-in runner must independently verify the core and seed, exercise trace-on
versus trace-off equivalence, runtime calibration, and both PAL and NTSC. None
of those checks has been performed here.

This is not a bus strobe, line/dot legality, physical hardware measurement,
actual ColourField visualization, or photosensitivity evidence. It does not
open the VDP publication gate or constitute an SMS port or video.
